**Контекст**
План предполагал, что зависимость CompactSlider 1.1.6 из Package.resolved соберётся как есть. Сборка с SDK macOS 27 это опровергла: пакет не компилируется.

**Решение**
CompactSlider 1.1.6 лежит локально в `Packages/CompactSlider` (лицензия MIT) и правится минимально, одной правкой, чтобы собираться с SDK macOS 27. Проект зависит от локального пакета.

**Почему**
- Обновить до 1.2.1 отвергнуто: эта версия тоже не собирается с SDK macOS 27.
- Перейти на 2.x отвергнуто: API несовместим с проектом, потребовалась бы переделка кода слайдеров, а это не локализация.
- Править пакет в кэше SPM или DerivedData отвергнуто: правка пропадёт при очистке и не воспроизводится на другой машине.
- Заменить слайдер своим отвергнуто: логика не меняется, меняются только строки.

**Последствия**
- Мы сами владеем копией чужого кода: исправления апстрима пакета не подтягиваются.
- Правку нужно сохранять в голове при любой смене SDK или версии.
- Лицензия MIT требует сохранять уведомление об авторстве в копии.
- В `Package.resolved` и в проекте появляется расхождение с апстримом Ice.
